Sommaire

    Le rôle du GM sur Commando Hubert

    Le Game Master (GM) est le metteur en scène de l’opération : il prépare le terrain, anime l’ennemi, fait monter la pression et arbitre. Il n’est ni un joueur ni un adversaire : son but est que les joueurs vivent une OPEX crédible, pas de les battre.

    Avant l’OPEXLire le brief du commandant d’opération, préparer les positions ennemies, les véhicules, le respawn et vérifier les budgets.
    PendantRester invisible, suivre la radio, doser les vagues, réagir aux initiatives des joueurs sans casser leur plan.
    AprèsNettoyer les entités, noter les prises et pertes de zones pour le front, participer au débrief.
    • Le RP prime : une embuscade bien placée vaut mieux que trois escouades spawnées à 50 m des joueurs.
    • Jamais de « deus ex machina » : pas de foudre, de téléportation ou de soin miracle sans raison RP (sauf bug ou sécurité).
    • Un seul GM pilote ; un second peut assister (reco, logistique) mais ne spawne pas sans accord.
    • Discrétion : les commandes et la caméra GM ne doivent pas trahir l’ennemi (pas de lampe GM en vue des joueurs, ne pas « survoler » bruyamment une position).

    Accéder au Game Master sur le serveur

    1. Une fois connecté sur le serveur, ouvrir le chat avec / (ou la touche de chat de vos contrôles).
    2. Taper #login motdepasse puis Entrée. Le mot de passe admin est différent du mot de passe du serveur : demandez-le à l’état-major, ne l’écrivez jamais sur le Discord ni ici.
    3. Appuyer sur Échap : une entrée Game Master apparaît dans le menu de pause. La sélectionner ouvre l’interface.
    4. Pour revenir à votre soldat : Échap puis quitter le Game Master. Pour rendre les droits : #logout.
    💡 Les commandes qui commencent par # sont traitées par le serveur et ne sont pas diffusées aux autres joueurs. En cas de doute sur vos droits, tapez #roles.
    ⚠️ Ne restez pas connecté en admin « par confort ». Un GM qui joue en même temps fausse le RP et un #restart ou un Suppr malheureux peut effacer une opération entière.

    L’interface du Game Master

    Caméra

    • ZQSD : déplacer la caméra ; clic droit maintenu + souris : tourner.
    • Monter / descendre : touches dédiées dans Options → Contrôles → Game Master (le wiki Bohemia indique Q et Z sur clavier QWERTY ; vérifiez votre disposition AZERTY).
    • M : carte, pour se repérer et déplacer la caméra ou une sélection à l’autre bout du terrain.
    • I : masquer / afficher l’interface (pratique pour observer ou faire une capture).
    • L : lampe de la caméra, visible du GM seulement, de nuit.

    Les panneaux

    • Barre d’outils (en haut) : visite guidée (icône chapeau d’étudiant), Nettoyer les entités détruites (libère le budget des morts et des épaves), carte, retour en jeu.
    • Navigateur d’entités Tab : tout ce qui se place. Filtres par faction, type, rôle, trait et contenu (jeu de base / mods). R remet les filtres à zéro, Échap ferme.
    • Propriétés du scénario (maintenir V) : factions jouables, points d’apparition, objectifs, heure, météo, respawn (détails plus bas).
    • Propriétés d’une entité : double-clic (ou clic droit → Modifier les propriétés) : santé, carburant, munitions, faction, comportement…

    Les budgets

    En bas à droite du navigateur d’entités, quatre jauges limitent ce que le serveur peut supporter : Objets (décors et compositions), IA (soldats contrôlés par l’ordinateur), Véhicules et Systèmes (points de respawn, objectifs, arsenaux…). À 100 % d’une jauge, rien de ce type ne peut plus être placé tant qu’on n’a pas supprimé ou nettoyé. Les autres jauges restent utilisables.

    💡 Faites Nettoyer les entités détruites après chaque phase : les morts et les épaves continuent de compter dans les budgets et pèsent sur les performances du serveur.

    Menu contextuel (clic droit sur une entité)

    • Soigner (santé à 100 %), Réapprovisionner (chargeurs et munitions), Refaire le plein (véhicules).
    • Déclencher un saignement : le soldat doit se bander — utile pour un exercice médic.
    • Mettre le feu / Éteindre, Foudre (détruit la cible : à réserver aux bugs, jamais sur un joueur).
    • Prendre le contrôle d’une IA : parler à la radio en tant qu’ennemi, conduire un véhicule, jouer un PNJ (informateur, officier capturé).
    • Modifier les propriétés : un mort ou une épave ne se « ressuscitent » pas ainsi ; placez une nouvelle entité.

    Diriger l’IA

    Un groupe se compose d’un chef et de ses soldats. Clic droit sur un soldat → Nouveau groupe pour le détacher, ou faites-le glisser sur un autre groupe pour l’y rattacher. Sélectionnez un groupe puis donnez-lui un point de passage (waypoint) :

    OrdreRaccourciComportement
    DéplacementAlt+1Rejoint le point en combattant ce qu’il croise ; terminé quand le chef arrive.
    Déplacement forcéAlt+2Ignore les ennemis en chemin : pour une colonne qui doit arriver coûte que coûte.
    Déplacement détenduAlt+3Marche, armes baissées : patrouilles de routine, ambiance avant l’assaut.
    Recherche et destructionAlt+4Ratisse la zone jusqu’à ce qu’il ne reste plus d’hostiles.
    DéfendreAlt+5Tient la position, ne se termine jamais tout seul.
    Monter à bordAlt+6Embarque dans le véhicule disponible le plus proche.
    • Les points de passage sont des ordres à l’IA, pas des objectifs de faction : l’IA ignore les objectifs du scénario.
    • Enchaînez plusieurs points pour un itinéraire ; le dernier Défendre fixe la position finale.
    • Pour une contre-attaque crédible : une colonne en Déplacement forcé jusqu’à 400–600 m, puis Recherche et destruction sur la zone.
    • Spawnez l’ennemi hors de vue (derrière une crête, dans un bois, à l’intérieur d’un bâtiment) et en avance : l’IA a besoin de quelques secondes pour se mettre en place.

    Gérer les joueurs

    • Téléporter un joueur : sélectionner le joueur, puis Téléporter le joueur dans son menu (ou glisser-déposer). À réserver aux blocages (joueur coincé, bug de spawn).
    • Soigner / réapprovisionner un joueur : uniquement pour corriger un bug, jamais pour « sauver » une escouade — c’est le rôle des médics et de la logistique.
    • Neutraliser un joueur : seulement si l’état-major impose une mort RP ou en cas de triche flagrante.
    • Respawn : dans les propriétés du scénario (V), activer la réapparition, le délai et l’option « près des opérateurs radio ». Annoncez les règles de respawn au brief.
    ⚠️ Retirer une faction jouable tue instantanément tous les joueurs qui lui sont assignés. Ne touchez pas aux factions pendant une opération.

    Réglages du scénario (maintenir V)

    FactionsFactions jouables, leurs points d’apparition et leurs objectifs. Les objectifs servent aux joueurs ; l’IA les ignore.
    Heure et dateHeures rapides (05:45, 08:52, 12:00, 20:12, 22:06, 00:00) ou curseur par pas de 15 min. Écoulement du temps 0,1× à 12× (1× par défaut).
    MétéoAutomatique ou forcée : dégagé, nuageux, couvert, pluie, brouillard. Le brouillard change tout pour une infiltration.
    VentAutomatique ou forcé : 0 à 15 m/s, huit directions. À prendre en compte pour l’aéro et les fumigènes.
    RespawnActivation, délai, apparition près des opérateurs radio.
    MusiqueMusique d’ambiance pour tout le serveur : coupez-la en OPEX sérieuse.

    Changer l’heure ou la météo en pleine opération se voit : faites-le avant le lancement ou pendant une pause RP, et avec parcimonie.

    Checklist d’une OPEX

    J-1 / avant le lancement

    1. Lire l’ordre d’opération du commandant : objectif, zone, effectif, moyens, horaire.
    2. Vérifier la situation du front : la zone visée, son état, les zones voisines ennemies (c’est de là que vient la contre-attaque).
    3. Préparer les positions ennemies hors de vue, les véhicules, les points de respawn, l’heure et la météo.
    4. Garder au moins 30 % de budget IA et véhicules pour réagir en cours d’opération.
    5. Tester le respawn et l’arsenal avec un joueur de l’état-major avant d’ouvrir le serveur.

    Pendant

    1. Suivre la radio de commandement : adaptez l’ennemi au plan des joueurs, ne contrez pas chaque idée.
    2. Rythme en trois temps : approche calme → contact → contre-attaque ou extraction sous pression.
    3. Une vague à la fois ; nettoyer les entités détruites entre deux vagues.
    4. Noter dans le chat GM ou un bloc-notes : heure des prises, pertes, événements marquants (pour le journal du front).

    Après

    1. Nettoyer tout ce qui reste (IA, véhicules, objets) pour la session suivante.
    2. Mettre à jour le front dynamique si une zone a changé de camp.
    3. Débrief avec le commandant : ce qui a marché, ce qui est à corriger côté GM.

    Erreurs classiques

    • Spawner en vue des joueurs ou dans leur dos sans logique RP.
    • Sur-spawner : plus de budget, serveur qui rame, joueurs épuisés.
    • Oublier de désactiver la lampe GM ou l’interface avant de reprendre son soldat.
    • Changer l’heure ou la météo brutalement.
    • Faire un #restart en croyant « recharger la mission ».

    Le mod GM Tools

    GM Tools (Workshop, auteur H0VI) ajoute au Game Master une boîte à outils pilotée depuis le chat : avertissements aux joueurs, téléportation, caméra sur un joueur, grades, nettoyage du serveur, fin de session propre, alertes vers le Discord et journal des sessions GM. Tout se fait avec des commandes qui commencent par #, après un #login (voir Accéder au Game Master).

    Commandes de chatAvertir, téléporter, suivre, nettoyer, terminer : sans ouvrir l’interface du GM.
    DiscordAlerte formatée vers un webhook (avec mention de rôle et délai anti-spam) et, en option, copie du chat du jeu.
    PopupsMessages à l’écran pour un joueur, une faction ou tout le monde, avec titre, durée et son.
    Journal GMEntrées et sorties du mode GM enregistrées avec la durée de chaque session.
    Vision nocturne GMLuminosité de la vision nocturne du GM adaptée à la météo.
    NettoyagePurge des corps, épaves et objets placés pour soulager le serveur.

    Fiche du mod : reforger.armaplatform.com/workshop/64F10E068D5880A6 (version 2.2.0 pour le jeu 1.7 au 30 mai 2026). Sa licence interdit toute utilisation sur un serveur monétisé.

    Configuration côté serveur

    1. Au premier démarrage avec le mod, un dossier GM_Tools apparaît dans le profil du serveur ($profile:/GM_Tools/) avec deux fichiers : gm_tools_config.json (à modifier) et GM_Tools_README.txt (référence générée automatiquement, à ne pas éditer : il se met à jour quand de nouveaux réglages arrivent).
    2. Les réglages couvrent l’activation de chaque fonction, l’adresse du webhook Discord des alertes (m_sAdminAlertWebhookURL), la copie du chat vers Discord (m_bDiscordChatForwardingEnabled), les textes et sons des popups et les valeurs de luminosité de la vision nocturne.
    3. Après une modification : redémarrer le serveur, ou #gmtools -reload si vous n’avez changé que des valeurs existantes.
    4. #gmtools -status en jeu confirme ce qui est actif.
    ⚠️ L’adresse du webhook Discord donne le droit d’écrire dans le salon : elle reste dans le fichier de configuration du serveur, jamais sur le Discord ni sur ce site.

    Bonnes pratiques

    • Un popup est intrusif : un message court, clair, et pas plus d’un par problème.
    • Le journal des sessions GM existe pour ça : l’état-major peut voir qui a tenu le GM et combien de temps — jouez le jeu et sortez du mode GM quand vous reprenez votre soldat.
    • La copie du chat vers Discord concerne tous les joueurs : si elle est activée, annoncez-le dans le règlement.
    • Après une mise à jour du jeu, vérifiez sur la fiche du mod qu’une version compatible est sortie avant de relancer le serveur.

    Pourquoi une économie

    L’économie donne un prix aux choix tactiques : partir avec un lance-roquettes, demander un blindé ou monter une FOB doit se décider, se préparer et se ravitailler. Elle crée le lien entre les opérations (le front dynamique), la logistique et le RP.

    • Les ressources se gagnent par les objectifs et le ravitaillement, pas par le temps de connexion.
    • Elles se dépensent à l’arsenal, pour les véhicules et pour construire.
    • Le GM et l’état-major arbitrent : ils ne distribuent pas, ils encadrent.

    Ravitaillement (supplies) du jeu de base

    Dans les scénarios de type Conflict, la ressource s’appelle ravitaillement (supplies). Elle se stocke dans les bases et les dépôts, et tout ce qui s’y prend ou s’y construit en consomme.

    • Arsenal : chaque équipement a un coût ; prendre un équipement lourd vide le stock de la base.
    • Construction : services d’une base (armurerie, hôpital de campagne, garage, antenne radio…) et fortifications coûtent du ravitaillement.
    • Transport : les camions de ravitaillement chargent dans une base ou un dépôt et déchargent dans une autre — c’est le cœur de la logistique.
    • Côté GM : la quantité de ravitaillement d’une base, d’un dépôt ou d’un camion se règle dans ses propriétés (double-clic sur l’entité). Un arsenal placé par le GM peut aussi être limité ou illimité selon ses propriétés.
    💡 Pour une OPEX, préférez un stock de départ serré et une FOB à ravitailler plutôt qu’un arsenal illimité : la logistique devient une mission à part entière.

    Rôle du GM et de l’état-major

    • Le GM ne remplit pas un stock vide en pleine opération : il laisse la logistique faire son travail, ou prévoit un convoi ennemi à capturer.
    • Toute correction manuelle (bug, perte injustifiée) se note : qui, quand, combien, pourquoi.
    • Abus (duplication, exploitation d’un bug, farming hors RP) : avertissement puis sanction selon le règlement ; le gain indu est retiré.
    • Les barèmes changent rarement et toujours par annonce sur le Discord, jamais en cours de session.

    Le principe

    Le front dynamique est la campagne persistante du serveur : la carte est découpée en zones (villes, villages, bases, aérodromes, ports, points clés), chacune tenue par un camp — le Commando, l’ennemi ou personne — avec un niveau de contrôle de 0 à 100 %. Ce que les joueurs prennent ou perdent en OPEX reste acquis d’une session à l’autre, et la page d’accueil du site l’affiche en direct.

    ZonesReliées entre elles par des liaisons. Une liaison entre deux camps opposés forme la ligne de front.
    OpérationsAssaut des joueurs, contre-attaque de l’IA ou attaque annoncée, avec chronos, vagues et progression.
    FOBUne zone avec FOB sert de point de départ et de ravitaillement ; elle se voit sur la carte du site.
    JournalLes événements marquants (prise, perte, annonce, vague, mission, FOB, défense) ; le site affiche les 6 derniers.

    Le cycle de vie d’une zone

    • calmeRien ne se passe. L’IA tient ses zones à 100 % ; une zone neutre est à 0 %.
    • menacéeUne attaque ennemie est annoncée : le journal prévient, les chronos tournent. Le GM prépare la colonne.
    • assautLes joueurs attaquent une zone ennemie ; la progression de la capture monte de 0 à 100.
    • fragilePrise récente : la zone est à nous mais le contrôle est bas et une contre-attaque est probable.
    • contre-attaqueL’IA revient par vagues (ex. 2/3). Tenir jusqu’à la dernière vague fait passer la zone en sécurisée.
    • sécuriséeZone stabilisée, contrôle élevé. C’est typiquement là que s’installe une FOB.

    Une zone prise mais abandonnée (aucun défenseur) peut repasser à l’ennemi : c’est l’événement perte du journal. Les contre-attaques partent des zones ennemies voisines : regardez les liaisons avant de choisir un objectif.

    Le bandeau « Situation du front » du site

    En haut de index.html, le bandeau lit un document JSON publié par le serveur de jeu et se met à jour tout seul (toutes les 2 minutes, ou en continu quand la source est une base Firebase). Il affiche le rapport de force, la carte schématique, les opérations en cours, le journal et le tableau de toutes les zones.

    Statut affichéSignification
    En directLe document change régulièrement : le serveur publie normalement.
    Sans nouvellesAucun changement depuis 2,5 fois la période annoncée (5 min pour un envoi toutes les 2 min). Le site garde la dernière situation connue.
    Serveur arrêtéLe serveur a publié serveur.enLigne = false avant de s’arrêter.
    DémonstrationLe document porte "demo": true (données fictives, horaires rejoués au présent).

    Les réglages sont sur la balise <section id="front"> de index.html :

    • data-source : adresse du flux. En production : https://front-dynamique-default-rtdb.europe-west1.firebasedatabase.app/front.json. Pour revenir à la démonstration : data/front.json.
    • data-mode : auto (défaut), flux (écoute continue) ou lecture (relecture périodique).
    • data-intervalle : secondes entre deux relectures (120 par défaut).

    Publier la situation

    Automatiquement, par le mod

    • Seul le serveur publie (Replication.IsServer()) : toutes les 2 minutes et à chaque événement (prise, perte, annonce de contre-attaque), jamais plus d’une fois toutes les 10 s.
    • L’adresse de la base et le secret d’écriture sont lus dans un fichier de configuration du serveur (ex. $profile:FrontDynamique/flux.json) : jamais dans le mod publié sur le Workshop.
    • Le document pèse quelques Ko (20 zones ≈ 8 Ko). Les envois partiels (front/operations.json, front/journal.json) ne remplacent que ce morceau.
    • Pas de pseudo de joueur dans le journal public sans son accord.

    À la main (correction, test, fin de campagne)

    1. Récupérer la situation actuelle : ouvrir l’adresse …/front.json dans un navigateur et enregistrer le fichier.
    2. Modifier ce qu’il faut (camp d’une zone, état, contrôle, journal). Garder "demo": false et mettre "maj" à l’heure actuelle (secondes Unix UTC).
    3. Renvoyer le document depuis un terminal, avec le secret d’écriture : 
      curl -X PUT -d @front.json \

    Comment ça marche

    • Le calendrier s’ouvre toujours sur la semaine en cours, le jour actuel en surbrillance, et avance tout seul chaque jour. Les boutons permettent de regarder les semaines suivantes.
    • Votre pseudo est mémorisé dans ce navigateur (lettres, chiffres, tiret et souligné, sans accent, 24 caractères maximum). Chaque GM répond sous son propre pseudo : le compte de connexion du site, lui, est commun.
    • Les réponses sont enregistrées dans la base Firebase du front (nœud agenda) : tout le monde voit les mêmes, depuis n’importe quel appareil.
    • Pour corriger : recliquez sur le jour et choisissez une autre réponse, ou « Effacer ma réponse ».
    • Les cases affichent le nombre de GM présents : pratique pour caler une OPEX.

    Configuration de la base (état-major)

    L’agenda lit et écrit dans la Realtime Database du projet front-dynamique, nœud agenda. Pour l’autoriser, remplacer les règles de la base (console Firebase → Realtime Database → onglet Règles → Publier) par :

    {
  "rules": {
    ".read": false,
    ".write": false,
    "front": { ".read": true },
    "agenda": {
      ".read": true,
      "$jour": {
        ".validate": "$jour.matches(/^20[0-9][0-9]-[01][0-9]-[0-3][0-9]$/)",
        "$gm": {
          ".write": true,
          ".validate": "$gm.matches(/^[A-Za-z0-9_-]+$/) && $gm.length <= 24 && newData.isString() && (newData.val() == 'present' || newData.val() == 'absent' || newData.val() == 'peut-etre')"
        }
      }
    }
  }
}
    • Le front ne change pas : lecture publique, écriture réservée au mod (avec le secret).
    • Pour l’agenda : lecture publique ; écriture sans mot de passe, mais uniquement une date au format AAAA-MM-JJ, un pseudo simple et l’une des trois valeurs present, absent, peut-etre. Rien d’autre ne peut être écrit.
    • C’est le même niveau de protection que l’espace membres : suffisant pour un agenda de disponibilités, pas pour des données sensibles. En cas d’abus, retirer le bloc agenda des règles suffit à tout bloquer.
    • Tant que les règles ne sont pas publiées, le statut affiche « Base non configurée pour l’agenda » et les réponses ne s’enregistrent pas.
    • Pour utiliser une autre base : changer l’attribut data-agenda du bloc <div id="agenda"> dans admin.html.
